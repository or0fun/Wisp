## 0.3.0 配置引导与权限诊断

- Debug / Release 构建、`codesign --verify --deep --strict` 和源 / 产物 plist 校验通过。
- 新增首次启动三步配置引导；快捷入口、后台权限、可选工具分别展示，支持跳过、完成与重新打开。引导进度独立于业务配置。
- 临时运行时冒烟通过：首次展示 / 跳过 / 完成的持久化，权限与安全输入变化，前台触发和错误快捷键不通过验证，只有匹配的后台触发通过，撤销授权后清除连续按键验证，配置变化中断测试，组合键验证不依赖辅助功能授权，以及进度文件 `0600` 权限。未添加单元测试。
- 独立预览界面确认：首次进入引导，三步切换、权限不足时禁用后台测试、工具状态和当前应用路径展示正确。预览不申请系统权限。
- 在预览中把间隔改为 600 ms，进入引导后返回设置，仍显示 600 ms 和「有未保存的更改」；还原后恢复 400 ms，正式设置未受影响。
- 通过界面从系统通用「辅助功能」页点击新版授权入口，确认跳转到「隐私与安全性 → 辅助功能」应用列表。旧链接在本机跳到了通用辅助功能页，已替换为现代系统设置扩展链接。参考 [Chromium 的系统设置实现](https://chromium.googlesource.com/chromium/src/+/887a4da09bff3ee39b5799e78554f2d3bf5bd4f5/base/mac/mac_util.mm)。
- 故障现场确认：系统列表中的 PersonalAI 开关已开启，但 0.2.0 应用内实际 `AXIsProcessTrusted()` 仍为 false；安全输入未开启。已安装应用的 designated requirement 为 cdhash，属于 ad-hoc 临时签名。旧授权可能不匹配当前构建，不能将列表开关等同于运行进程已获授权。
- 构建脚本支持 `PERSONALAI_SIGNING_IDENTITY` 使用本机已有开发者签名；当前环境没有可用签名身份，产物仍使用 ad-hoc 签名，引导展示更新后重新授权说明。没有新建证书或降低签名要求。
- 按此前覆盖安装授权，备份 0.2.0 并安装 0.3.0 到 `/Applications/PersonalAI.app`；正式界面确认当前路径、双击 ⌘ / ⌘3 / ⌥⌘Space 配置保留，显示「系统实际授权未生效」「等待辅助功能授权」。
- 系统授权由用户手动重新添加当前应用后生效。界面再次确认「系统实际授权：已生效」「全局监听已建立」「安全输入：未开启」，并出现最近后台键盘事件时间。
- 用户随后实际操作并确认双击 ⌘ 能从其他应用正常唤起。此项为用户实机确认；引导中的专门测试流程仍显示尚未进行，没有据此声称应用内测试标记已通过。自动粘贴仍未实测。
